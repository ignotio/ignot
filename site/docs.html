How it works, and how to run it

ignot is a command line and an engine written in Rust. An exam is a folder of plain files, so everything on this site can be checked with tools you already have.

Build it

git clone https://github.com/ignotio/ignot
cd ignot
cargo install --path crates/ignot-cli

It needs Rust. Nothing else is installed, and no account or key is needed to seal, open or verify.

One exam, start to finish

ignot make --id 2026-w48
ignot seal 2026-w48.plain.json --open +7d
ignot open exams/2026-w48
ignot run exams/2026-w48 \
  --models deepseek/deepseek-v4.1-flash,anthropic/claude-haiku-5.5
ignot verify exams/2026-w48
  • make draws a random seed and writes the questions with their answer keys.
  • seal encrypts that file to a drand round, writes manifest.json and exam.age, and deletes the plain file.
  • open works only after the round. It writes exam.json.
  • run asks every model every question and writes answers/ and results.json. It reads OPENROUTER_API_KEY. Run it again to add models or a track. An answer that was paid for is never asked for again: a run that was cut short, or had failed requests, goes on where it stopped.
  • verify checks everything below. verify-all exams does it for every folder.

Two tracks

Same budget. Every model gets the same money for each question, $0.02 unless the exam says otherwise. Cheap tokens buy longer thinking. A right answer that cost more than the budget does not count, and the runner sees to it that question and answer together cannot cost more at the prices the model lists. When the cheapest host is busy, the price cap is raised by half, up to three times, and the model gets the tokens the budget buys at that price.

No limit. Every model thinks at high effort, with up to 32,000 output tokens for each question.

On both tracks a model that many hosts serve is asked at the cheapest host that is up, and each answer names the host that served it. Left to itself the provider spreads requests over hosts that charge several times the listed price.

The price of intelligence is what a model spent on a track, divided by its right answers.

Grading

Each reply must end with a line ANSWER: .... Grading is mechanical: numbers within 0.005, exact strings, or lists of tokens. No model grades another, and nobody grades by hand.

Questions come in ten kinds, each at five levels: program tracing, table filtering, shortest paths with a hop limit, string transformations, a teller queue, mixed-base arithmetic, a stack machine, a grid robot, digit counting, and a chain where part two needs the answer to part one. They are generated by code in the repository from the seed, so an opened exam can be rebuilt byte for byte.

What verify checks

  1. The sealed file matches the hash in the manifest, and is locked to the manifest's drand round.
  2. The open time in the manifest is the drand round's publish time.
  3. While the exam is sealed, nothing of it is published: no questions, no answers, no scores.
  4. After the round, the round's signature is drand's own: it is checked against the beacon's public key before anything is opened.
  5. The sealed file opens with that signature and matches the hash of the paper.
  6. The questions regenerate byte for byte from the revealed seed.
  7. Every model answered every question once, and every stored reply grades to the same result again.
  8. The results file and its Merkle root recompute from the replies.
  9. The seal and the results root match the record on chain, in the one contract whose address is part of the code. No record contract is deployed yet, so these two checks show as waiting.

A check that cannot be made is shown as not made, never as passed. The same code runs in your browser on every exam's page, compiled to WebAssembly.

The files

exams/pilot-01/
  manifest.json   id, open round, the hashes of the file and the paper
  exam.age        the sealed paper, a standard tlock ciphertext
  exam.json       the paper, once it has been opened
  answers/        every raw reply, one file for each model
  results.json    the scores of each track, and the Merkle root

Hashes are SHA-256. A leaf of the tree holds every field of one answer's record, with the reply replaced by its hash. Money is counted in whole billionths of a dollar, so no sum rounds.

Seal your own files

ignot seal-file notes.txt --open +10m
ignot open-file notes.txt.age --out opened.txt

--open takes a time such as 2026-12-03T14:00:00Z or a delay such as +90m, +6h or +2d. The second command fails until the time has passed. The file is a standard tlock ciphertext, so other tlock tools open it too. The home page does the same thing without a terminal.

Read it from a script

The site serves the exam folders as they are, and one index of them. Nothing needs a key.

# the index: every manifest, every results file, every path
GET /api/exams.json
# the folders, as they are
GET /exams/pilot-01/manifest.json
GET /exams/pilot-01/exam.age
GET /exams/pilot-00/exam.json
GET /exams/pilot-00/results.json
GET /exams/pilot-00/answers/<model>.json

The contracts

ExamSeals records a seal while its round is still in the future, and a results root only after the round has opened. It holds no funds and cannot be upgraded.

StumpBox takes a fixed burn, sent straight to the dead address, for one sealed question of at most 4,096 bytes. It never holds a token.

Both are in the repository with their tests. Their addresses are listed here when they are deployed.
